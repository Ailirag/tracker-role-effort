# Трудозатраты по ролям — плагин Яндекс Трекера

Показывает план и факт трудозатрат в разрезе ролей (разработчик, аналитик,
тестировщик и любые другие). Соответствие полей задаётся **отдельно для каждой
очереди**, поэтому плагин не привязан к схеме конкретной организации и пригоден
для публикации.

## Как это работает

- **План** берётся из числового поля роли — того, где хранится оценка в часах.
- **Факт** собирается из ворклогов: время относится к роли, если автор ворклога
  указан в поле-исполнителе этой роли.
- Всё, что сопоставить не удалось, показывается строкой
  «Не распределено по ролям» — заниженный факт остаётся видимым.

## Точки встраивания

| Слот | Где | Что показывает |
|---|---|---|
| `issue.block` | секция на карточке задачи | план/факт по ролям для одной задачи |
| `queue.tab` | вкладка очереди | сводка по выборке задач + экран настроек |

## Доступ к настройкам

Вкладка «Настройки» видна только тем, у кого есть право `GRANT` на очередь, то
есть тем, кто её администрирует. Право проверяется запросом
`GET /queues/{id}/checkPermissions/GRANT` про текущего пользователя: оно может
быть выдано напрямую, через группу или через роль, и разобрать это на клиенте
по спискам держателей нельзя.

Сводка при этом доступна всем, кто видит очередь.

Хранилище настроек живёт в контексте организации и о правах на очередь не знает,
поэтому его собственный флаг `canWrite` этот доступ не ограничивает — проверка
права обязательна и стоит перед ним. Важно понимать границу: скрытие вкладки —
это разграничение интерфейса, а не защита данных.

Настройки можно скопировать из другой очереди — выбор очереди в шапке формы.
Копирование только заполняет форму, сохранение остаётся отдельным действием;
поля, которых в текущей очереди нет, перечисляются предупреждением.

```bash
npm install

```


## Публикация

```bash
npx @weavix/cli submit
```

Материалы для каталога подготовлены:

- `public/logo.svg` — квадратный логотип;
- `marketplace/header-image.jpg` — картинка карточки, 1205×500 (2,41:1);
- `marketplace/index.md` — полное описание, 2926 символов из 4000 допустимых;
- `support[0].value` в `manifest.json` — контакт поддержки.

Картинка карточки собирается скриптом `tools/make-header.py`: он перерисовывает
`marketplace/header-image.jpg`, если понадобится изменить текст или цвета.

Краткое описание в манифесте ограничено 75 символами и не заканчивается точкой —
это требование каталога, оно строже, чем ограничение схемы манифеста (255).

Приватная публикация — плагин появляется в каталоге организации после одобрения
администратором. Публичная — только через обращение в поддержку с архивом
исходного кода.

## Ограничения, о которых важно знать

1. **Массовый поиск не возвращает пользовательские поля ролей.** Их отдаёт
   только запрос одной задачи, поэтому сводка по очереди догружает каждую задачу
   отдельно. Объём выборки ограничен (25/50/100); при обрезке показывается
   предупреждение, а не молчаливо неполные итоги.
2. **Хранилище настроек.** `storageApi` не описан в публичной документации.
   В установленной версии SDK доступен только контекст организации
   (`orgShared`), поэтому очередь кодируется в имени бакета
   (`role-effort.<КЛЮЧ_ОЧЕРЕДИ>`; двоеточие в имени бакета запрещено схемой —
   допустимы только буквы, цифры, точка, подчёркивание и дефис).
   Контекст сущности (`resource`) появляется в
   более новых версиях и подхватывается автоматически — формат данных не меняется.
3. **Пути API.** Вызовы собраны в `src/core/trackerClient.ts`. Набор типизированных
   путей зависит от версии пакета, поэтому обращения идут через узкий помощник:
   при расхождении правка нужна в одном файле.
4. **Конфликт настроек.** Сохранение использует версию записи; если настройки
   изменил кто-то другой, запись перечитывается, а не затирается.

## Структура

```
manifest.json              — манифест: слоты, разрешения, метаданные
issue-block.html           — точка входа слота issue.block
queue-tab.html             — точка входа слота queue.tab
src/core/
  types.ts                 — модель настроек и результатов
  duration.ts              — разбор ISO-8601 длительностей в часы
  effort.ts                — расчёт плана и факта по ролям
  trackerClient.ts         — все обращения к API Трекера
  settingsRepository.ts    — чтение и запись настроек очереди
  useQueueSettings.ts      — хук загрузки/сохранения настроек
  aggregate.ts             — сбор данных по выборке задач
src/ui/
  RoleEffortTable.tsx      — таблица план/факт
  SettingsForm.tsx         — настройка соответствия полей
src/slots/                 — приложения слотов
```
